# Prototype Process

IDEA
↓
DESIGN SEED — one sentence: "I want to test whether X is fun"
↓
SMALLEST PLAYABLE PROTOTYPE — test ONE question
↓
PLAYTEST — play it yourself for 5 minutes
↓
IDENTIFY THE PROBLEM — is the core question answered?
↓
ITERATE — change one thing at a time
↓
PLAYTEST AGAIN
↓
PROMOTE SUCCESSFUL SYSTEMS — only if clearly reusable
↓
POLISH — only after the mechanic is validated

## Good prototype questions

- Is this movement mechanic fun?
- Is this risk/reward decision interesting?
- Is this combat interaction satisfying?
- Does this puzzle create meaningful choices?
- Does the core loop have tension?

## Rules

- One prototype tests ONE question.
- Do not build a complete game before validating the core mechanic.
- A failed prototype is still useful — you learned something.
- Promote a system to `src/systems/` only when two or more prototypes need it.
